\section*{How to read this deck}

\begin{frame}{One claim per slide}
\topic{How to read the deck: one claim per slide, colour banners, three bubbles.}
Purpose: walk through what SHEAF computes --- equation, assumption,
unit, and source --- with the Agrimate authors.

\begin{itemize}
\item Blue \textbf{About.} line: plain English, then the equation below.
\item Tiny \textbf{Symbols.} line: each letter on that slide, with meaning and unit.
\item Each slide states \textbf{one claim}.
\item The equation is the one in README \S8 (crisis host) or \S1--\S6
      (leftover). That is the specification.
\item Three bubbles: \textbf{parameter} (what is free / locked),
      \textbf{unit}, \textbf{source} (which file, which vintage).
\item Green banner = README \S8 (or the leftover \S1--\S6 claim) and the
      code match. The equation is the specification.
\item Grey banner = the annual SPE leftover in \texttt{sheaf/core.py}.
      It is still in the repository. It is \textbf{not} the 2007/08 host.
\item Red is reserved if a displayed claim and the code still disagree.
      After the README catch-up, the crisis-host slides are green.
\end{itemize}

\vspace{0.2em}
{\scriptsize \textbf{Running order.} Lineage $\to$ the two hosts and the
one-step spine $\to$ clock and units $\to$ source data $\to$ harvest
forcing $\to$ the step's equations in the order they run $\to$ method of
solution $\to$ locked parameters and Gate~0 scores $\to$ Gate~1 $\to$
Gate~2 $\to$ annual leftover $\to$ questions.}
\syms{\S8 the crisis-host section of \texttt{README.md} \symsep \S1--\S6 the
annual-leftover sections of the same README \symsep Gate~0 the locked
single-crop 24-step market; Gate~1 adds cross-grain substitution; Gate~2 adds
endogenous export cuts \symsep green banner = displayed claim matches the code;
grey = annual leftover; red = a live disagreement.}
\end{frame}

\begin{frame}{The verification protocol (from \texttt{CLAUDE.md})}
\topic{How we checked a claim against the code, and how we classify a mismatch.}
For every suspected mismatch we did, in order:

\begin{enumerate}
\item Locate the mathematical claim (README equation or docstring).
\item Locate the implementation (file and line).
\item Compare, symbol by symbol where feasible.
\item Attempt a numerical counterexample.
\item Attempt to prove the implementation correct on its own terms.
\item Only then classify.
\end{enumerate}

Classification is not ``wrong vs right vs Agrimate.'' Categories:
\textbf{A} math error, \textbf{B} coding bug, \textbf{C} numerical,
\textbf{D} economic simplification, \textbf{E} modeling philosophy,
\textbf{F} empirical gap, \textbf{G} documentation, \textbf{H} holds.

A departure from Deaton--Laroque is \textbf{E}, not \textbf{A}, if SHEAF
never claimed that equilibrium.
\syms{``claim'' a specific README equation, section, or docstring statement
\symsep ``implementation'' a specific file and line range in \texttt{sheaf/}
\symsep ``counterexample'' a concrete input or parameter set on which claim and
code disagree numerically \symsep Deaton--Laroque the rational-expectations
competitive-storage benchmark.}
\end{frame}
