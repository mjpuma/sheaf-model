## First attempt (failed, 2026-09-30 18:00Z)

Both runs failed right after Nash init with

```text
ERROR: LoadError: MethodError: no method matching generate_forced_harvest_timeseries(::Float64, ::Vector{Float64}, ::Vector{Union{Missing, Float64}}, ::Vector{Float64}; year_start=2000, n_start=1, N_year=24, t_max=312, N_hor=24)
  ... at src/preprocess.jl:445, called from src/simulation.jl:239
```

In the reconstructed anomaly CSV, 44 non-producing countries had a trend of
0, so the anomaly came out as 0/0 = NaN, and pandas wrote that as a blank.
CSV.jl reads a blank cell as `missing`. The paper code sums the file over
each region's countries before forming `1 + anomaly/trend`, so the regions
containing those countries became `missing`. `replace(NaN => 1)` does not
catch `missing`.

Writing literal `NaN` (the first suggestion in this note) would have been
wrong. The region sum would be NaN, `replace` would turn it into 1, and every
real anomaly in those regions would be silently lost.

## Input fix and vetting

`scripts/build_agrimate_paper_inputs.py` changes (details in `INPUTS.md`):

1. Non-producers and any year with trend ≤ 0 carry exact zeros in both the
   anomaly and trend files. The script now refuses to write non-finite values.
2. Export restrictions are merged per exporter into non-overlapping
   intervals at the daily maximum cut. The paper's
   `aggregate_export_restrictions` adds overlapping values and caps the sum
   at 1. AMIS repeats a measure once per rate revision, so the old file
   stacked to a 100% cut on Argentina from May 2007 to May 2012 and on China
   through 2008. The max rule is the one `sheaf/agrimate/restrictions.py`
   used. It went from 117 raw rows to 49 intervals.

Food balance, trade flows, harvest distributions and parameters were
byte-identical after the rebuild, so the J2 baseline still matches the
inputs. The old files are kept in `agrimate-2025/agrimate_input_backup_pre_j3fix/`.

Checks run before relaunch:

- Python, all seven files: no blank cells except the intended `STU`/`A_d`
  blanks for 138 zero-consumption countries (the paper imputes medians); all
  256 AgrimateEU28 ISO codes present once; no negatives; trade has no
  self-flows or duplicates and each exporter's sum equals its food-balance
  exports; harvest distributions sum to 1; trend ≥ 0 everywhere, anomaly 0
  wherever the trend is 0, and 0 before 2005; restrictions have From ≤ To, no
  overlaps, values 0.5–0.95.
- Julia, `agrimate-2025/vet_j3_inputs.jl`: replays the input lines of
  `simulate()` (no Nash init, no time loop) with the J3 settings. The
  forcings are `Float64`. `generate_harvests` returns 28 finite,
  non-negative series of length 336. Region forcings for 2005–2013 range from
  0.49 to 1.59, for example Australia 2006 0.56, Russia 2010 0.80, Kazakhstan
  2010 0.66. The effective per-step restriction cuts peak at 0.95
  (Argentina, India, Kazakhstan, Russia), 0.70 (Ukraine), 0.68 (China after
  export-share scaling) and 0.50 (Egypt), and no step is at 1.0. All
  restricted exporters are model producers. Log:
  `agrimate-2025/vet_j3_inputs.log`.

Left as is, for J4 to weigh:

- The J2 log warns that inferred internal flow is negative for Southeast
  Asia (−3%) and Western Africa (−18%). The paper code sets it to zero. The
  same inputs, and the same warning, apply to all three runs.
- The AMIS "Wheat" class gives Egypt a 0.5 cut from 2008-06-30 onward.
  Egypt exports very little wheat, so the effect after export-share scaling
  should be small.
