# J4 — Gate 0 score: local Julia runs vs author NetCDF

> **Superseded in part (2026-10-01):** the harvest + restrictions numbers below used the unclipped restriction file (data problem 1). That file is now clipped to 2007–2011 and the scenario is being rerun (`J3.md`, "Rerun"). They stand only until the rerun is re-scored.

**Verdict: not a reproduction.** This is a run of the published Agrimate
code on SHEAF-reconstructed inputs. It does not reproduce the published
wheat run. The three runs share the author's broad shape: the same price
peak month, the same sign of most shock effects, and monthly price
correlation of 0.83–0.91. They miss on levels. World stocks are 30 % too
high. The 2007/08 harvest-shock price spike is about 30 % too small. The
restriction scenario restricts a different set of regions. Several
calibrated parameters are off by a factor of 2 to 9. Nothing was retuned.

## What was run

- Script: `scripts/compare_agrimate_julia_runs.jl`, run read-only with
  the paper project's NCDatasets under Julia 1.6.5 (Rosetta). The command
  is at the top of the script. Its output was kept out of the repo.
- Local: the three J2/J3 files in
  `agrimate-2025/agrimate-equal-sales-penalty/data/netcdf/`.
- Author: the three files with the same names in
  `agrimate-2025/data-v3/data/hindcasting_analysis/raw_data/`.
- Aggregation follows the paper's `src/plot.jl`. Harvest and consumption
  are summed per calendar year. Stocks are producer + consumer storage at
  the last step of the year. The **world market (WM) price index** is the
  paper's `plot_wm_price_timeseries` definition: the monthly mean
  transaction price over non-domestic flows, weighted by export volume.
  Units are 1000 t (the file attribute). Prices are a unitless index, with
  the calibrated baseline price ≈ 1.
- `sheaf/agrimate/` is a different program (the paused Python rewrite).
  It was not compared.

## What matches

- World baseline harvest (632.1 vs 631.6 Mt/yr, +0.1 %) and consumption
  (+0.1 %). Regional harvest shares correlate at 0.997.
- The calibrated baseline price is the same (1.0003 vs 1.0002).
- Price peaks in **May 2008** in both shock runs, local and author.
- World harvest anomalies 2006–2012 have the same signs and similar sizes.
  For example 2007 is −26.2 vs −32.1 Mt and 2008 is +33.9 vs +29.7 Mt.
  2005 does not match: +10.9 vs −8.1 Mt.
- The restriction mark-up on price is close: 07/08 +10.6 % vs +9.3 %,
  10/11 +12.4 % vs +11.8 %. Because the restricted regions differ (below),
  this agreement is partly coincidence.
- Most per-region shock effects on consumption have the same sign.

## Data problems found

1. **The reconstructed `export-restrictions_crop=wheat_source=2007-2011.csv`
   is not limited to 2007–2011.** It holds AMIS measures through 2024, for
   example IND to 2013-03, CHN to 2015-06 and EGY to 2021-12. Restrictions
   therefore stay on to the end of the run for five exporters. The
   author's restrictions all end by 2011-09.
2. The author restriction set covers different regions. It has Pakistan,
   Eastern Africa, Rest of Europe, Rest of Western Asia and Rest of
   Southern Asia, and no India or Egypt. AMIS alone does not reproduce that
   set. The author source is unknown.
3. In the author files Middle Africa has no producer. In the
   reconstruction it has one.
4. The reconstructed STU, A_d and A_c (`INPUTS.md`) are well away from the
   values the author code calibrated. This is the main source of the
   stock gap.
5. Code identity cannot be confirmed (`gitcommit` and `script` above).
   The 100–500× wall-time gap is also unexplained.

None of these were fixed in J4. Fixing item 1 would be an input-build
correction, not a retune. It would need a rebuild and a rerun of the
harvest + restrictions scenario, which is outside this prompt.

## Classification

**A run of the published code on reconstructed inputs. Not a reproduction
of the published wheat run.** The qualitative 2007/08 story holds: a May
2008 peak, with the harvest shock and restrictions both adding to it. The
published magnitudes are not reproduced: stocks +30 %, a harvest spike
30 % too small, almost no 2010/11 harvest spike, and different restricting
regions. A failed match stays failed. Gate 0 is not accepted by this note.
J6 needs the user's explicit acceptance of this score.
